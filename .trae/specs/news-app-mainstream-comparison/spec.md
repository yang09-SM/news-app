# 新闻APP与主流产品对比分析 & 迭代升级路线图 Spec

## Why

本项目基于RuoYi 4.8.3框架构建的新闻管理系统，已实现22张业务表、36个API端点、完整用户体系和基础推荐算法。但与今日头条、腾讯新闻、网易新闻等2025-2026年主流新闻APP相比，在**技术架构、实时性能、AI能力、内容生态、运营工具**等维度存在显著差距。本规格文档系统性地识别所有差距，并制定分阶段迭代升级方案。

### 技术栈现状
- **后端**: Spring Boot 4.0.3 + MyBatis + Shiro + Ehcache

### 二、技术架构差距

| 维度 | 主流APP架构 | 本项目现状 | 影响评估 |
|------|-------------|------------|----------|
| **应用架构** | 微服务/K8s容器化 + Service Mesh | 单体Spring Boot(Maven多模块) | 扩展性受限，单点故障风险 |
| **前端技术** | Vue3/React SPA + SSR首屏渲染 | Thymeleaf服务端渲染 | 无法支持移动端H5/App |
| **API设计** | GraphQL + RESTful + gRPC | RESTful仅支持JSON | 不够灵活，移动端请求冗余 |
| **缓存策略** | CDN → Nginx本地缓存 → Redis Cluster → DB | 无CDN，无Redis，仅Ehcache(Shiro会话) | 热点新闻无法承受突发流量 |
| **数据库** | 分库分表(ShardingSphere/TiDB) + 读写分离 | 单MySQL实例 | 大数据量时性能急剧下降 |
| **搜索引擎** | Elasticsearch/OpenSearch集群 | MySQL LIKE '%keyword%' | 全文搜索慢、无分词、无高亮 |
| **消息队列** | Kafka/RocketMQ/Pulsar | 无异步队列 | 所有操作同步阻塞，无法削峰 |
| **文件存储** | 阿里云OSS/腾讯COS + CDN分发 | 本地upload目录 | 无法横向扩展，无CDN加速 |
| **推荐引擎** | TensorFlow/PyTorch深度模型 + 特征平台 + 召回服务 | Java内存协同过滤(几百行代码) | 推荐精度低，冷启动差 |
| **实时计算** | Flink/Spark Streaming实时特征 | 无实时计算能力 | 无法做实时推荐和实时统计 |
| **监控告警** | Prometheus + Grafana + ELK日志 | 若依自带简单日志 | 故障发现慢，排查困难 |
| **CI/CD** | GitLab CI/Jenkins + Docker + K8s部署 | 手动mvn spring-boot:run | 发布效率低，无回滚机制 |
| **安全防护** | WAF + DDoS防护 + 接口签名 + 数据脱敏 | Shiro + XSS过滤器 + BCrypt | 缺少接口限流、防重放、数据加密传输 |

## ADDED Requirements

### Requirement: Redis缓存集成
系统SHALL引入Redis作为分布式缓存层，用于：
- 热门新闻TOP N列表缓存（TTL 5分钟）
- 新闻详情页缓存（TTL 10分钟，发布时主动失效）
- 推荐结果缓存（TTL 30分钟，按userId隔离）
- 分类/频道/作者等基础数据缓存（TTL 1小时）
- 分布式Session存储（替换Ehcache）

#### Scenario: 热点新闻缓存击穿保护
- **WHEN** 突发新闻导致同一篇文章被大量并发请求
- **THEN** 系统应使用互斥锁(Mutex)防止缓存击穿，确保只有一个请求回源DB

### Requirement: Elasticsearch全文搜索
系统SHALL引入Elasticsearch替代MySQL LIKE搜索：
- 支持中文分词(IK Analyzer)
- 搜索结果关键字高亮显示
- 搜索联想/自动补全(Completion Suggester)
- 搜索热词统计和排行
- 文章索引在发布/编辑时自动同步ES

#### Scenario: 搜索联想
- **WHEN** 用户在搜索框输入关键词（>=2字符）
- **THEN** 系统返回最多10条联想建议，包含标题匹配和历史搜索词

### Requirement: 云存储OSS集成
系统SHALL支持文件上传至阿里云OSS或腾讯COS：
- 图片上传(支持jpg/png/gif/webp，限制10MB)
- 视频上传(支持mp4/mov，限制500MB)
- 自动生成缩略图
- 返回可访问的URL（含CDN域名）
- 保留本地存储作为fallback降级方案

### Requirement: Push消息推送
系统SHALL集成第三方Push服务（极光推送/个推）：
- 全部用户推送（运营公告）
- 按标签/别名定向推送（分类偏好用户）
- 单点推送（@提及/私信通知）
- 推送送达统计（到达率/点击率）
- 后台管理界面（推送记录、新建推送任务）

### Requirement: 短视频播放器
系统SHALL提供完整的短视频播放能力：
- 支持MP4/HLS/DASH格式
- 播放/暂停、进度拖动、全屏切换
- 清晰度切换(720p/480p/360p)
- 播放速度调节(0.5x/1x/1.5x/2x)
- 自动连续播放(列表模式)
- 横竖屏自适应

### Requirement: 推荐算法升级
系统SHALL对现有推荐算法进行增强：
- 增加时间衰减因子（近期浏览权重更高）
- 增加多样性控制（避免信息茧房）
- 增加新鲜度加权（最新发布的文章获得额外曝光）
- 缓存推荐结果（相同用户5分钟内不重复计算）
- 冷启动优化（新用户注册时引导选择兴趣标签）

### Requirement: 广告管理系统
系统SHALL提供完整的广告管理能力：
- 广告位管理（首页Banner、信息流插卡、详情页底部、开屏广告）
- 广告素材管理（图片/视频/文案）
- 投放计划（起止时间、展示频次控制、目标人群定向）
- 曝光/点击统计（CTR计算）
- 广告状态管理（待审核/投放中/已结束）

### Requirement: 内容审核自动化
系统SHALL提供多层内容审核机制：
- 第一层：敏感词自动过滤（内置敏感词库，支持正则匹配）
- 第二层：AI内容审核接口（可选接入百度/阿里云/腾讯云内容安全API）
- 第三层：人工审核后台（现有ReportController增强）
- 审核结果记录和统计分析

### Requirement: 接口限流与风控
系统SHALL实现基础的接口安全防护：
- 基于注解的接口限流(@RateLimit)：支持IP维度/用户维度/接口维度
- 令牌桶算法(Token Bucket)：平滑限流
- 登录失败锁定（已有，需确认配置正确）
- 参数校验增强（防SQL注入、防XSS已有，需补充CSRF和SSRF防护）
- 操作日志审计（若依已有sys_oper_log，需确保覆盖新接口）
