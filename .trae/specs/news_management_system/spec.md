# 新闻管理系统 - 产品需求文档

## 概述
- **摘要**：在 RuoYi 后台管理系统基础上扩展新闻管理功能，包括用户权限管理和新闻内容管理
- **目的**：为新闻应用提供完整的后台管理能力，支持用户管理、权限控制和新闻内容发布
- **目标用户**：系统管理员、新闻编辑人员

## 目标
1. 扩展 RuoYi 现有用户和权限管理功能，支持新闻应用用户
2. 新增新闻分类管理功能
3. 新增新闻内容管理功能（发布、编辑、删除、审核）
4. 提供 API 接口供前端（Android/Web）调用

## 非目标
- 不修改 RuoYi 核心框架代码
- 不实现完整的内容审核流程（仅提供基本的发布/草稿状态）
- 不实现评论管理功能（第一期）

## 背景与上下文
- **现有系统**：RuoYi v4.8.3 是一个基于 Spring Boot 的后台管理系统，已包含用户管理、角色管理、菜单权限管理等功能
- **技术栈**：Java 17、Spring Boot 4.0.3、MyBatis、Thymeleaf、MySQL
- **现有功能**：用户管理、角色管理、菜单管理、部门管理、通知公告管理等

## 功能需求

### FR-1: 新闻分类管理
- 管理员可以创建、编辑、删除新闻分类
- 支持分类排序
- 支持分类启用/禁用状态

### FR-2: 新闻内容管理
- 管理员可以创建、编辑、删除新闻
- 支持富文本编辑
- 支持图片上传
- 支持新闻状态管理（草稿、已发布、已下线）
- 支持新闻分类关联
- 支持新闻搜索和筛选

### FR-3: 权限控制
- 基于 RuoYi 现有权限体系，为新闻管理功能添加菜单和按钮权限
- 支持不同角色拥有不同的新闻管理权限

### FR-4: API 接口
- 提供 RESTful API 供 Android 应用和 Web 前端调用
- API 包括：新闻列表、新闻详情、分类列表等
- API 支持跨域访问

## 非功能需求

### NFR-1: 性能
- 新闻列表查询响应时间 < 1s（1000 条数据以内）
- 支持分页查询

### NFR-2: 安全
- API 接口需要认证（基于 RuoYi 现有认证体系）
- 防止 SQL 注入、XSS 攻击

### NFR-3: 可维护性
- 代码遵循 RuoYi 现有架构和编码规范
- 提供完整的数据库变更脚本

## 约束

- **技术约束**：必须基于 RuoYi 现有架构扩展，不能重构核心框架
- **数据库**：使用 MySQL，与 RuoYi 共用数据库
- **前端技术**：使用 Thymeleaf + jQuery + Bootstrap（与 RuoYi 保持一致）

## 假设

1. RuoYi 系统已正确配置并可以正常运行
2. 数据库已正确初始化
3. 管理员已拥有系统超级管理员权限

## 验收标准

### AC-1: 新闻分类管理
- **前置条件**：用户已登录并拥有新闻分类管理权限
- **操作**：访问新闻分类管理页面，进行增删改查操作
- **预期结果**：
  - 可以创建新分类
  - 可以编辑现有分类
  - 可以删除分类（无关联新闻时）
  - 可以启用/禁用分类
  - 可以对分类进行排序
- **验证类型**：人工验证

### AC-2: 新闻内容管理
- **前置条件**：用户已登录并拥有新闻管理权限
- **操作**：访问新闻管理页面，进行新闻的增删改查操作
- **预期结果**：
  - 可以创建新闻（支持富文本编辑、图片上传）
  - 可以编辑新闻
  - 可以删除新闻
  - 可以改变新闻状态（草稿、已发布、已下线）
  - 可以按分类、状态、标题搜索新闻
- **验证类型**：人工验证

### AC-3: 权限控制
- **前置条件**：系统已配置好不同角色和权限
- **操作**：使用不同角色用户登录，测试新闻管理功能的访问权限
- **预期结果**：
  - 无权限用户无法访问新闻管理菜单
  - 只有拥有相应权限的用户才能执行相应操作
- **验证类型**：人工验证

### AC-4: API 接口
- **前置条件**：API 服务已启动
- **操作**：调用新闻相关 API 接口
- **预期结果**：
  - GET /api/news/list 返回新闻列表
  - GET /api/news/{id} 返回新闻详情
  - GET /api/category/list 返回分类列表
  - API 支持分页和筛选
  - API 返回正确的 JSON 格式数据
- **验证类型**：程序验证
